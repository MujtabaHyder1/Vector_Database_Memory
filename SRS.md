## 1. Executive Summary

This system builds **stateful learning agents** with persistent memory using ChromaDB and Ollama LLM. Unlike traditional chatbots, these agents:

- Maintain context across conversations
- Learn from past interactions (episodic memory)
- Know organizational policies (declarative memory)
- Share knowledge across teams (multi-agent learning)
- Generate better responses over time as memory grows

**Core Innovation**: Responses are informed by actual LLM (Ollama) with vector-retrieved context, not hardcoded lookups.

## 2. Functional Requirements

### FR1: Local LLM Integration (Ollama)
**Requirement**: System must use actual LLM for response generation  
**Implementation**: OllamaLLM class connects to local Ollama server  
**Verification**: 
- LLM connection verified on startup
- Every response is generated by Ollama, not lookup
- Context from memory is passed to LLM as prompt augmentation

**Test Case**:
```python
# Before memory loaded
query = "Can I work from home?"
response_no_mem = agent.process_query(query, use_memory=False)
# LLM generates generic response

# After memory loaded
response_with_mem = agent.process_query(query, use_memory=True)
# LLM generates informed response mentioning "2-3 days/week"
assert len(response_with_mem) > len(response_no_mem)
```

---

### FR2: Episodic Memory (Past Interactions)
**Requirement**: System must store specific past interactions  
**What is Stored**:
- Query text
- Response text
- Outcome (success/partial/failed)
- Timestamp
- Agent ID
- User ID
- Confidence score

**Implementation**: EpisodicMemory dataclass + ChromaDB collection  

**Test Case**:
```python
# Agent processes query
result = agent.process_query("How much vacation?")
# Stored in episodic memory
memories = memory_manager.recall_memory("vacation", "episodic", top_k=1)
assert len(memories) > 0
assert "vacation" in memories[0]['content'].lower()
```

---

### FR3: Declarative Memory (Facts & Policies)
**Requirement**: System must store organizational knowledge  
**What is Stored**:
- Fact/policy/rule text
- Category (policy/rule/fact/procedure)
- Source (where it came from)
- Confidence (how sure we are)
- Version (for tracking updates)

**Implementation**: DeclarativeMemory dataclass + ChromaDB collection  

**Test Case**:
```python
# Add a policy
agent.add_fact("Remote work: 2-3 days/week. Manager approval required.", 
               category="policy", source="it")
# Retrieve it
facts = memory_manager.recall_memory("working from home", "declarative")
assert len(facts) > 0
assert facts[0]['similarity'] > 0.7  # Semantic match
```

---

### FR4: Error Memory (Learning from Mistakes)
**Requirement**: System must track errors to avoid repeating them  
**What is Stored**:
- Error description
- Root cause
- Resolution
- Severity (low/medium/high)

**Implementation**: ErrorMemory dataclass + ChromaDB collection  

**Test Case**:
```python
# Log an error
agent.log_error(
    error_desc="Forgot to mention budget limit",
    root_cause="Incomplete knowledge",
    resolution="Always mention $2000 cap upfront",
    severity="medium"
)
# Retrieve when answering similar query
errors = memory_manager.recall_memory("laptop budget", "errors")
assert len(errors) > 0
```

### FR6: Multi-Agent Learning
**Requirement**: Multiple agents share the same persistent memory  
**Architecture**:
- HR Agent and IT Agent created
- Both use same PersistentVectorMemoryManager instance
- HR's episodic memories accessible to IT
- IT's declarative memories accessible to HR

**Implementation**: Single memory_manager instance passed to all agents  

**Test Case**:
```python

# IT agent can retrieve it

```

### FR7: Persistent Storage
**Requirement**: Memory survives notebook restart  
**Storage**: ChromaDB PersistentClient writing to disk  
**Location**: `~/.vector_memory/db/`  

**Implementation**: PersistentVectorMemoryManager uses persistent path  

**Test Case**:
```python
# Session 1
memory_manager = PersistentVectorMemoryManager()
```

### FR8: Semantic Search & Retrieval
**Requirement**: Find relevant memories despite different wording  
**Implementation**: 
- all-MiniLM-L6-v2 for 384-dim embeddings
- Cosine similarity scoring
- Top-K retrieval

**Test Case**:
```python
# Add memory about "laptop"
agent.add_fact("Laptop requests approved within 5 days")

# Query with different wording
results = memory.recall_memory("computer request", "declarative", top_k=1)
assert len(results) > 0  # Finds "laptop" despite saying "computer"
assert results[0]['similarity'] > 0.6  # High semantic match
```

### FR9: Memory-Informed Response Generation
**Requirement**: LLM responses use retrieved memory as context  
**Flow**:
1. Query received
2. Retrieve relevant memories (episodic + declarative + error)
3. Build context prompt from retrieved memories
4. Pass to Ollama: `generate(query, context=context_prompt)`
5. LLM uses context in response

**Implementation**: MemoryAwareAgent.process_query() method  

**Verification**: See Section 8 (Before/After)

## 5. Data Structures

### EpisodicMemory
```python
@dataclass
class EpisodicMemory(MemoryEntry):
    query: str              # What was asked
    response: str           # What was answered
    outcome: str            # success/partial/failed
    confidence: float       # How sure (0-1)
    user_id: str           # Who asked
```

### DeclarativeMemory
```python
@dataclass
class DeclarativeMemory(MemoryEntry):
    fact: str              # The fact/policy/rule
    category: str          # policy/rule/fact/procedure
    source: str            # Where it came from
    confidence: float      # How sure (0-1)
    version: int           # For tracking updates
```

### ErrorMemory
```python
@dataclass
class ErrorMemory(MemoryEntry):
    error_description: str # What went wrong
    root_cause: str        # Why it happened
    resolution: str        # How to fix it
    severity: str          # low/medium/high
```

## 6. Use Case Scenarios

### Use Case 1: New Employee Onboarding
**Actor**: HR Agent, New Employee  
**Flow**:
1. Employee: "What's the vacation policy?"
2. Agent retrieves declarative memory: "20 days/year, 10-day notice"
3. Agent adds to episodic memory: "New employee asked about vacation"
4. Agent: "You have 20 days vacation per year. 10-day notice required."
5. IT Agent later retrieves this interaction for context
**Result**: Consistent information across departments

---

### Use Case 2: Cross-Team Knowledge Sharing
**Actor**: HR Agent, IT Agent, Shared Memory  
**Flow**:
1. HR Agent learns: "Remote work restricted during 3-month probation"
2. Stored as declarative + episodic memory
3. IT Agent processes equipment request from probation-period employee
4. IT retrieves HR's memory about probation
5. IT correctly denies remote-work setup request
**Result**: Organizations learn from each other

---

### Use Case 3: Error Prevention
**Actor**: HR Agent  
**Flow**:
1. Agent gives wrong vacation accrual rate (error)
2. Logged to error memory with resolution
3. Next similar query retrieves this error
4. Agent proactively mentions correct policy first
**Result**: Agents avoid repeating mistakes

---

### Use Case 4: Context-Aware Responses
**Actor**: HR Agent, LLM  
**Flow**:
1. Same query asked twice (e.g., "How to request laptop?")
2. First time: No memory context → generic LLM response
3. Second time: Memory context retrieved → specific, policy-compliant response
**Result**: Responses improve as memory grows

## 9. Known Limitations & Future Work

### Limitations
1. **Memory size**: Not tested beyond 10K memories
2. **Context window**: LLM context limited by model
3. **Privacy**: No user isolation in this version
4. **Temporal**: No memory decay/freshness

### Future Enhancements
1. Memory decay (older memories less relevant)
2. User-specific memory isolation
3. Memory visualization dashboard
4. Feedback loops (rate response quality)
5. Distributed memory (multi-machine)
